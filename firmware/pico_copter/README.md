# Pico Copter firmware

このフォルダが、Raspberry Pi Picoへ書き込むファームウェアの独立したプロジェクトです。共有するときは`firmware/pico_copter`フォルダをそのまま取り出せます。

`.cpp`、`.hpp`、`.c`、`.h`は`github.dev`または通常のローカル開発環境で編集できます。変更履歴はGitで管理され、GitHub Actionsが変更後のファームウェアをコンパイルします。

## 必要なもの

- Raspberry Pi Pico SDK 2.3.0
- ARM GCC
- CMake 3.13以上
- Eigen 3.4.0

Eigenの場所を指定しない場合、CMakeが公式Eigenの固定コミットを自動取得します。

## ビルド例

```bash
cmake -S . -B build \
  -DPICO_SDK_PATH=/path/to/pico-sdk \
  -DPICO_BOARD=pico \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build --parallel
```

生成物は`build/pico_copter.uf2`です。

既にEigenを持っている場合は、次を追加できます。

```bash
-DEIGEN3_INCLUDE_DIR=/path/to/eigen
```

## i-26 からの移植について

このファームウェアは `pico-copter-uf2-builder` を土台に、`i-26` の制御・PWM・SBUS等の変更を移植しています。**モータミキシングでは `R_com`（Yaw補正）の符号だけ元のPico Copterを維持しています。現在はスロットルの使用可能範囲を再スケーリングし、姿勢補正項に `0.9 / BATTERY_VOLTAGE` を掛けています。**

### PWM GPIO（現行基板：i-26 実装に準拠）

| Output | GPIO | Pico physical pin |
|---|---:|---:|
| RL | 2 | 4 |
| RR | 3 | 5 |
| FL | **14** | **19** |
| FR | **15** | **20** |
| Servo | 6 | 9 |

PWMピンを変更する場合は `pwm.hpp` の `PWM_PIN_*` を変更します。メインループは `PWM_MAINLOOP_PIN` のPWMラップ割り込み（400Hz）に同期します。

### 実機に書き込む前の注意

- 現行基板では FL=GPIO14 / FR=GPIO15 を使用します。i-26 のREADMEの GPIO4 / GPIO5 は旧配線を示しており、現在の `pwm.hpp` には適合しません。
- i-26 に合わせてPIDパラメータとSBUS範囲が変更されているため、送信機のキャリブレーションやゲインの再確認が必要です。
- モータミキシングの符号は i-26 に準じ、`R_com` の符号だけ Pico Copter のオリジナルを維持しています。スロットル基準値は使用可能範囲に合わせて換算します。
- プロペラを外して各軸の応答・回転方向・フェイルセーフを確認してください。

## CH5操作による100 Hzリングバッファ記録

飛行中のログは**CH5をONにした間だけ**記録します。アームするだけでは記録せず、CH5をOFFにするとその時点の直近約10秒分をRAMに保持します。

| 操作・状況 | 記録の動作 |
|---|---|
| 電源投入・アーム | 記録しない。アーム後にCH5のOFF状態を確認してからONを受け付ける |
| 飛行中にCH5をON | 新しい記録として開始（以前のデータを置き換える） |
| CH5をONのまま | 100 Hzで38項目を1行として連続記録し、満杯なら最古の行を上書き |
| CH5をOFF | 次の100 Hz処理で記録を凍結し、データを消去しない（停止遅延は通常10 ms以内） |
| ディスアーム・通信断 | 記録していた場合は凍結。自動再記録しない |
| 停止後に再びCH5をON | 前の記録を消去して新しい記録を開始 |
| ディスアーム中の既存ログ出力操作 | RAMの実データだけ古い順にUSBシリアル出力。出力後も保持 |
| 再アーム（CH5はOFF） | 以前の記録を保持。新たにCH5をONにするまで上書きしない |

- **記録周期:** 公称100 Hz。リアルタイムの制御・推定を優先し、リング記録以外の処理周期は変更しません。
- **記録内容:** 既存の38項目をそのまま維持します。
- **容量:** 1,000行×38個のfloat＝**152,000バイトの固定RAM**。公称10秒分。
- **CH5の判定:** 現行のCH5中間値より上でON、下側でOFF。
- **出力時刻:** 記録開始からの公称時間で、リングが一周しても出力行の時刻は連続します。実測タイムスタンプではありません。
- **負荷対策:** CH5 OFF時は38項目の行生成・RAM書込みを行わず、CH5 ON時だけ実行します。RAM上で完結し、記録中のシリアル出力やフラッシュ書込みは行いません。

**注意:** RAMのため電源OFFでデータは消失します。新しいCH5 ONでも前の記録を上書きするため、必要なデータは再記録の前にPCへ取り出してください。実機での動作確認は必ずプロペラを外してください。

## Raspberry Pi Pico（RP2040）を優先して双方向DShot300を試験

GitHub Actionsでは**初代Pico (RP2040) と Pico 2 (RP2350)**を同じソースコードから**別々にビルド**します。
今回の試験対象は初代Picoです。必ず対象基板に合ったUF2を使用してください。

| 基板 | CMakeの指定 | 配布ファイル |
|---|---|---|
| Raspberry Pi Pico | `-DPICO_BOARD=pico` | `pico_copter.uf2` |
| **Raspberry Pi Pico 2** | **`-DPICO_BOARD=pico2`** | **`pico_copter_pico2.uf2`** |

GitHub Pagesでは初代Picoが初期選択になっています。互換性のため初代Pico用の
`firmware/manifest.json` と `pico_copter.uf2` は維持し、
Pico 2用の `manifest-pico2.json` も残っていますが、今回の実機評価は初代Picoで行います。

- GPIO2/3/14/15の双方向DShot300、GPIO6サーボPWM、PWMスライス7の制御周期、
  400 Hz角速度制御、100 Hz姿勢制御、SBUSフェイルセーフ、CH5ログの仕様は共通です。
- 初代Picoのシステムクロックは標準125 MHz、Pico 2は標準150 MHz。
  **PWM分周比を起動時にクロックから計算**するため、どちらも
  制御周期とサーボPWM周期を400 Hz（2.5 ms）に維持します。
  PIOの双方向DShot300送受信クロックも従来どおり動的に計算します。
- PID/EKF、モータミキシング、ログの38項目に変更はありません。
- 初代PicoでのコンパイルとUF2生成はGitHub Actionsで検証できますが、
  実機での通信成功率・制御周期のジッタは未検証です。
  プロペラを外してモータ停止・各GPIOの信号・DShot出力とスロットル追従を確認してください。

### DShot300モータ指令の範囲（全域使用）

現在の`control.cpp`は、モータを回す場合の各モータ出力値`duty`を
`0.10〜0.95`に制限しています。この出力を`dshot_protocol.hpp`で
**DShotの全回転指令範囲48〜2047**に線形変換します。

| 制御側の出力値 | DShot指令値 |
|---|---:|
| 停止（`motor_stop()`、`duty=0`） | **0（停止）** |
| `0.10`（回転時の下限） | **48（回転指令の下限）** |
| `0.525`（中間） | 約1048 |
| `0.95`（回転時の上限） | **2047（回転指令の上限）** |

有効範囲内では `DShot = round(48 + 1999 × (duty - 0.10) / 0.85)` です。
小さな正の値は48に、大きな値は2047に飽和します。
停止は常にDShot `0`、特殊コマンド`1〜47`は使用しません。
**PID、モータミキシング、スロットルの停止判定、400 Hz制御周期は変更していません。**

**注意：これは従来の408〜1767付近への変換からの変更です。**
ESCの回転数、特に停止条件解除直後と上限付近の挙動が変わります。
必ずプロペラを外して停止指令、最低回転指令、最大指令の挙動を確認してください。
現在は停止条件解除後からスロットル全開までを0.10〜0.95に再スケーリングしています。
ただし実際のモータ回転数が指令に比例するとは限りません。

## 修正：CH3スロットル出力が停止／最大の2択になる問題

実機のUSBログでは、CH3は368〜1680に変化していた一方で、
DShot指令が`0`（停止）と`2047`（最大）にほぼ固定されていました。
原因は、`T_ref`を電圧スケールのまま`*0.9`していたため、
**スロットル停止条件が解除される前にモータdutyが0.95に飽和した**ことです。

次のように**スロットルの使用可能範囲だけを再スケーリング**します。

- CH3の値は今までどおりSBUSで368〜1680を受信し、
  `T_ref = 0.6 * 11.1 * (CH3-368)/(1680-368)` を計算します。
- 停止条件`T_ref / 11.1 < Disable_duty(0.10)`は**変更しません**。
  通常の操縦ではCH3が約587以上で運転指令が有効になります。
- 運転時の基準出力（姿勢補正が0の場合）を、停止条件解除時の
  `duty=0.10`からCH3最大値で`duty=0.95`へ直線的に割り当てます。
- P/Q/RのPID補正量の符号とモータの割り当ては変えず、
  補正量には元の倍率`0.9`と電圧→無次元dutyの換算`/11.1`を適用します。
  4モータ合成後の`duty=0.10〜0.95`制限も維持します。
- DShot値は既存の変換で`duty=0.10 → 48`、
  `duty=0.95 → 2047`となり、中間値も使用できます。

**変更しない機能：**アーム／ディスアーム操作、通信断時のDShot 0停止、
400 Hz・100 Hz制御周期、PIDゲイン、EKF、CH5記録、サーボGPIO6とモータGPIO配置。DShotの送信方式だけは一方向へ変更しました。

**重要：**モータ指令の特性が従来と変わります。
実機動作は未確認なので、プロペラを外した状態で、
`#DBG SBUS ch3`→`#DBG MIX FR`→`#DShot300 cmd`の変化、
停止条件、4基の回転方向と姿勢補正の符号を検証してください。
ESC接続前にオシロスコープでDShotの実際の波形を確認するのが安全です。
元の実装にはGitHubの履歴から戻せます。

## 現行構成：初代Pico（RP2040）で双方向DShot300

**Pico 2（RP2350）から、初代Raspberry Pi Pico（RP2040）へ試験対象を変更しました。**
ESC信号を遮断する一方向レベルシフタを載せない**別基板**で、双方向DShot300の返信を調べます。
既存の基板をそのままジャンパしてレベルシフタ出力と競合させる構成ではありません。

| モータ | GPIO | Pico物理ピン |
|---|---:|---:|
| FR | 15 | 20 |
| FL | 14 | 19 |
| RR | 3 | 5 |
| **RL（今回の1モータ試験）** | **2** | **4** |
| サーボ（PWM） | 6 | 9 |

- PIO0の4ステートマシンで**反転DShot300**を送信後、GPIOを入力に切り替えESCのeRPM返信を受信します。標準一方向DShotとは**送信極性とCRCが異なります**。
- 16ビットの指令送信は約53.3 µs、返信開始までの待機は約25 µs、返信先頭検出の待ち時間は約43 µsに延長しています（以前は約8 µs）。21ビットの返信を約375 kbit/sで取り込みます。返信信号の検出が遅い場合に出力を早く再有効化しないための調整です。
- ESCの返答がなくても400 Hzの送信を停止せず、次周期で結果を確認する非ブロッキング方式。PID・EKF・スロットル変換・フェイルセーフ・CH5記録の制御にはeRPMを使用しません。
- スロットル停止時はDShot 0、回転時は48〜2047。モータ補正符号、PIDゲイン、400 Hz/100 Hz周期は変えません。
- RP2040用の配布ファイルは`pico_copter.uf2`です。`pico_copter_pico2.uf2`を初代Picoへ書き込まないでください。ビルダーの初期選択は初代Picoです。
- 従来の一方向DShot300版はコミット`2ed49dcd35af65c0a592df5d8b10def4ff508090`から復元可能です。

### USBシリアル診断（通常のメインループのみ）

USB CDC端末に`#DBG STATE`、`#DBG SBUS`（CH1〜CH6と受信鮮度）、`#DBG MIX`（T/P/Q/Rおよびモータ出力）、`#DShot300`（4モータ）を表示します。
ディスアーム時0.5秒、アーム時1秒ごとです。CH5リングログの出力中には表示を控えます。

`#DShot300 RL mode=bidir duty=... cmd=... pkt=... eRPM=... valid=... rx=... timeout=... gcr=... crc=... other=... busy=...`

- `cmd`はPIOへ最後に投入したスロットル指令、`pkt`は送信した**双方向用の論理パケット**（オシロ測定値ではありません）。
- `valid=1`なら最新のeRPM受信結果、`eRPM`は電気的回転数（機械回転数は極対数で除算）。`valid=0`なら直近250 ms以内の有効eRPMがないことを表します。
- `rx`は正常受信回数、`timeout`は返信なし、`gcr`/`crc`は復号エラー、`busy`は新しい送信を開始できなかった回数です。
- eRPMが読み取れなくてもモータ指令は継続します。ログだけではGPIO上の波形やESCとの電気的相性は証明できません。

### 実機前の電気的な確認

**プロペラを必ず外し、ESCを1組だけ接続して試験してください。**
ESCの信号電圧が初代Pico GPIOの許容範囲内（3.3 V系）であること、双方のGND共通、レベルシフタなど他の出力がESC信号線へ接続されていないことを確かめてください。
ESCの電源（2〜8S側）と信号電圧は別のものです。**ESCの信号線に5 Vが出る場合、初代Picoへ直結しないでください。**
まずオシロスコープで指令送信後の返信が正常な振幅であることを確認し、USBログの`rx`が増えるか調べてください。
返信待ちを延長しましたが、受信成功と飛行安定性は実機未確認です。

## SBUS communication-loss protection

- `sbus_parser.hpp`: 完全な25バイトフレームのみ解析し、フレームロスト/フェイルセーフフラグを確認。
- `radio.cpp`: 正常なフレームの最終受信時刻を記録し、100 msの通信監視を実施。
- `control.cpp`: 異常検出時にアームを解除、モータに最小ESC指令を送信。通信復帰後はスロットル低・アーム操作解除を200 ms維持し、通常の再アーム操作を必須にする。
- `tests/test_sbus.cpp`: フレーム解析、通信タイムアウト、復帰条件の単体テスト。

**注意:** DShot 0の停止指令は電源遮断ではありません。受信機がフェイルセーフフラグなしで古いチャンネル値を送信し続ける場合は通信断を検出できません。プロペラを外して実機確認してください。
