# Pico Copter FC

Raspberry Pi PicoおよびPico 2用のPico Copterファームウェアを、GitHub Actionsでコンパイルし、最新のUF2をGitHub Pagesからダウンロードするためのリポジトリです。


## 派生元と移植範囲

- ベース: [pico-copter-uf2-builder](https://github.com/temesotejam/pico-copter-uf2-builder)
- 変更の移植元: [i-26](https://github.com/temesotejam/i-26)
- **Yaw補正 `R_com` の符号は元のPico Copter、P/Qの補正符号とPIDゲインはi-26準拠です。** 従来の `T_ref * 0.9` による早期飽和は修正し、停止解除後のスロットル範囲をモータdutyへ適切にスケーリングしています。
- 移植する変更: PIDパラメータ、EKF呼び出し、PWM GPIO設定・IRQ処理・出力競合検査、SBUS入力範囲など。
- `i26-pico-firmware` は今回の移植元ではありません。ToF、RGB LEDなどの追加機能は含みません。

### 現行基板の配線（i-26 準拠）

| 出力 | 元のPico Copter | このリポジトリ（i-26準拠） |
|---|---:|---:|
| Rear Left | GPIO 2 | GPIO 2 |
| Rear Right | GPIO 3 | GPIO 3 |
| Front Left | GPIO 4 | **GPIO 14** |
| Front Right | GPIO 5 | **GPIO 15** |
| Servo | GPIO 6 | GPIO 6 |

**現行基板は i-26 の実装ピン配置です。** FL/FR は GPIO 14/15 を使用し、旧基板の GPIO 4/5 には戻しません。i-26 側の README に書かれた FL/FR=GPIO 4/5 は実装と一致していません。

ミキシングの `P_com` / `Q_com` の符号・構造は i-26 と同じで、`R_com` の符号のみ Pico Copter のものです。補正項には **`0.9 / 11.1`** を適用し、スロットル基準出力は停止解除後から全開まで **`0.10〜0.95`** に割り当てます。旧版の `T_ref * 0.9` は飽和のため使いません。

プロペラを外して初期動作を確認してください。コードの移植は飛行安全性やビルドの成功を保証するものではありません。

## RC link failsafe

SBUS受信安全処理（`firmware/pico_copter/sbus_parser.hpp`）を追加しています。

- 有効なSBUSフレームが100 ms届かない場合、最小ESC指令へ移行してアーム解除
- SBUSのフェイルセーフフラグを検出した場合、直ちに安全状態に移行
- 単発のフレームロストは有効受信に数えず、100 msタイムアウトで判定
- 通信復帰後はスロットル低・アーム操作解除を200 ms継続し、改めて通常のアーム操作を必要とする
- 起動直後も受信確認まではアームできない
- CIでSBUSフレーム解析と復帰判定のテストを実施

**制限:** 停止指令はESCへのDShot 0であり、モータの電源遮断ではありません。受信機が古いスティック値を正常なSBUSフレームとして送信し続け、フェイルセーフを通知しない設定の場合、通信断を判別できません。受信機の設定を確認し、プロペラを外して検証してください。

## CH5操作による100 Hzリングバッファ記録

飛行中のログは**CH5をONにした間だけ**記録します。アームするだけでは記録せず、CH5をOFFにするとその時点の直近約10秒分をRAMに保持します。

| 操作・状況 | 記録の動作 |
|---|---|
| 電源投入・アーム | 記録しない。アーム後にCH5のOFF状態を確認してからONを受け付ける |
| 飛行中にCH5をON | 新しい記録として開始（以前のデータを置き換える） |
| CH5をONのまま | 100 Hzで38項目を1行として連続記録し、満杯なら最古の行を上書き |
| CH5をOFF | 次の100 Hz処理で記録を凍結し、データを消去しない（停止遅延は通常10 ms以内） |
| ディスアーム・通信断 | 記録していた場合は凍結。自動再記録しない |
| 停止後に再びCH5をON | 前の記録を消去して新しい記録を開始 |
| ディスアーム中の既存ログ出力操作 | RAMの実データだけ古い順にUSBシリアル出力。出力後も保持 |
| 再アーム（CH5はOFF） | 以前の記録を保持。新たにCH5をONにするまで上書きしない |

- **記録周期:** 公称100 Hz。リアルタイムの制御・推定を優先し、リング記録以外の処理周期は変更しません。
- **記録内容:** 既存の38項目をそのまま維持します。
- **容量:** 1,000行×38個のfloat＝**152,000バイトの固定RAM**。公称10秒分。
- **CH5の判定:** 現行のCH5中間値より上でON、下側でOFF。
- **出力時刻:** 記録開始からの公称時間で、リングが一周しても出力行の時刻は連続します。実測タイムスタンプではありません。
- **負荷対策:** CH5 OFF時は38項目の行生成・RAM書込みを行わず、CH5 ON時だけ実行します。RAM上で完結し、記録中のシリアル出力やフラッシュ書込みは行いません。

**注意:** RAMのため電源OFFでデータは消失します。新しいCH5 ONでも前の記録を上書きするため、必要なデータは再記録の前にPCへ取り出してください。実機での動作確認は必ずプロペラを外してください。

## Raspberry Pi Pico 2（RP2350）対応

GitHub Actionsでは**初代Pico (RP2040) と Pico 2 (RP2350)**を同じソースコードから**別々にビルド**します。
Pico 2に初代Pico用UF2を書き込まず、必ず対象基板に合ったファイルを使ってください。

| 基板 | CMakeの指定 | 配布ファイル |
|---|---|---|
| Raspberry Pi Pico | `-DPICO_BOARD=pico` | `pico_copter.uf2` |
| **Raspberry Pi Pico 2** | **`-DPICO_BOARD=pico2`** | **`pico_copter_pico2.uf2`** |

GitHub Pagesで対象基板を選択できます。互換性のため初代Pico用の
`firmware/manifest.json` と `pico_copter.uf2` は維持し、
Pico 2用には `manifest-pico2.json` を追加しています。

- GPIO2/3/14/15の一方向DShot300、GPIO6サーボPWM、PWMスライス7の制御周期、
  400 Hz角速度制御、100 Hz姿勢制御、SBUSフェイルセーフ、CH5ログの仕様は共通です。
- 初代Picoのシステムクロックは標準125 MHz、Pico 2は標準150 MHz。
  **PWM分周比を起動時にクロックから計算**するため、どちらも
  制御周期とサーボPWM周期を400 Hz（2.5 ms）に維持します。
  PIOの一方向DShot300送信クロックも従来どおり動的に計算します。
- PID/EKF、モータミキシング、ログの38項目に変更はありません。
- Pico 2でのコンパイルとUF2生成はGitHub Actionsで検証できますが、
  実機での通信成功率・制御周期のジッタは未検証です。
  プロペラを外してモータ停止・各GPIOの信号・DShot出力とスロットル追従を確認してください。

### DShot300モータ指令の範囲（全域使用）

現在の`control.cpp`は、モータを回す場合の各モータ出力値`duty`を
`0.10〜0.95`に制限しています。この出力を`dshot_protocol.hpp`で
**DShotの全回転指令範囲48〜2047**に線形変換します。

| 制御側の出力値 | DShot指令値 |
|---|---:|
| 停止（`motor_stop()`、`duty=0`） | **0（停止）** |
| `0.10`（回転時の下限） | **48（回転指令の下限）** |
| `0.525`（中間） | 約1048 |
| `0.95`（回転時の上限） | **2047（回転指令の上限）** |

有効範囲内では `DShot = round(48 + 1999 × (duty - 0.10) / 0.85)` です。
小さな正の値は48に、大きな値は2047に飽和します。
停止は常にDShot `0`、特殊コマンド`1〜47`は使用しません。
**PID、モータミキシング、スロットルの停止判定、400 Hz制御周期は変更していません。**

**注意：これは従来の408〜1767付近への変換からの変更です。**
ESCの回転数、特に停止条件解除直後と上限付近の挙動が変わります。
必ずプロペラを外して停止指令、最低回転指令、最大指令の挙動を確認してください。
現在は停止条件解除後からスロットル全開までを0.10〜0.95に再スケーリングしています。
ただし実際のモータ回転数が指令に比例するとは限りません。

## 修正：CH3スロットル出力が停止／最大の2択になる問題

実機のUSBログでは、CH3は368〜1680に変化していた一方で、
DShot指令が`0`（停止）と`2047`（最大）にほぼ固定されていました。
原因は、`T_ref`を電圧スケールのまま`*0.9`していたため、
**スロットル停止条件が解除される前にモータdutyが0.95に飽和した**ことです。

次のように**スロットルの使用可能範囲だけを再スケーリング**します。

- CH3の値は今までどおりSBUSで368〜1680を受信し、
  `T_ref = 0.6 * 11.1 * (CH3-368)/(1680-368)` を計算します。
- 停止条件`T_ref / 11.1 < Disable_duty(0.10)`は**変更しません**。
  通常の操縦ではCH3が約587以上で運転指令が有効になります。
- 運転時の基準出力（姿勢補正が0の場合）を、停止条件解除時の
  `duty=0.10`からCH3最大値で`duty=0.95`へ直線的に割り当てます。
- P/Q/RのPID補正量の符号とモータの割り当ては変えず、
  補正量には元の倍率`0.9`と電圧→無次元dutyの換算`/11.1`を適用します。
  4モータ合成後の`duty=0.10〜0.95`制限も維持します。
- DShot値は既存の変換で`duty=0.10 → 48`、
  `duty=0.95 → 2047`となり、中間値も使用できます。

**変更しない機能：**アーム／ディスアーム操作、通信断時のDShot 0停止、
400 Hz・100 Hz制御周期、PIDゲイン、EKF、CH5記録、サーボGPIO6とモータGPIO配置。DShotの送信方式だけは一方向へ変更しました。

**重要：**モータ指令の特性が従来と変わります。
実機動作は未確認なので、プロペラを外した状態で、
`#DBG SBUS ch3`→`#DBG MIX FR`→`#DShot300 cmd`の変化、
停止条件、4基の回転方向と姿勢補正の符号を検証してください。
ESC接続前にオシロスコープでDShotの実際の波形を確認するのが安全です。
元の実装にはGitHubの履歴から戻せます。

## USB診断ログ（一方向DShot300）

USB CDCのシリアル端末を接続すると、400 Hz制御割り込み外の通常処理から診断情報を表示します。初期化・ディスアーム中は約0.5秒ごと、アーム中は約1秒ごとです。CH5記録ログの出力中は診断表示を停止します。

- `#DBG STATE`：起動時間、アーム状態、フェイルセーフ、CH5記録など
- `#DBG SBUS`：CH1〜CH6受信値、通信の鮮度、SBUSのフェイルセーフフラグなど
- `#DBG MIX`：推力目標`T`、PID補正`P/Q/R`、FR/FL/RR/RLのミキシング後duty（ディスアーム中は直前値が残る場合あり）
- `#DShot300`：各モータの要求duty、**PIOへ最後に投入した**`cmd`（0=停止、48〜2047=回転）、`pkt`（通常DShotの16ビット、通常CRC）、`tx`（送信指示回数）、`busy`（残存TX FIFOデータを破棄した回数）

出力例（値は説明用の架空の数値）：

```text
#DShot300 RL mode=oneway duty=0.235 cmd=366 pkt=0x2dc3 tx=12000 busy=0
```

※`pkt`は測定した波形ではなく、**ソフトウェアが生成した論理フレーム**です。実際の信号幅・極性・ESCでの受信成功や回転数はオシロスコープ等で検証してください。通常の一方向DShotなので、**eRPM・受信成功率・RX timeoutは表示・取得しません**。旧コードの`dshot_bidir_decode.hpp`は現在のファームウェアの送信処理に使用しません。

## 一方向DShot300（通常極性、ESCへの送信のみ）

GPIO2/3/14/15から一方向DShot300を送信し、GPIO6は従来のサーボPWMを維持します。

| モータ | GPIO | Pico物理ピン |
|---|---:|---:|
| FR | 15 | 20 |
| FL | 14 | 19 |
| RR | 3 | 5 |
| **RL** | **2** | **4** |

- 通常DShotの**非反転信号**と**通常CRC**を送ります。テレメトリ要求ビットは0に固定です。
- 16ビット×3.333 µs = **約53.3 µs/フレーム**。制御周期は**400 Hz（2.5 ms）**です。
- 各フレームの終了後にESCの応答を待ったり、GPIOを入力へ切り替えたりしません。
- 停止時・ディスアーム中・SBUSフェイルセーフ時は各モータへ**DShot 0（STOP）**を継続送信します。特殊コマンド1〜47は送信しません。
- スロットルの停止判定、0.10〜0.95のduty、DShot48〜2047への線形変換、PID・EKF・モータミキシング・SBUS・サーボ・CH5ログは変更しません。
- PIO送信プログラムは以前の一方向DShot版（`01cad80ac3fd60f4d3a2e7cc3f981279db3e04e0`）をベースにしています。双方向DShot版はGit履歴から確認できます。

**注意：プロペラを外した状態でESC 1組から試してください。** まずSTOPで停止すること、CH3に対して`#DShot300 RL cmd`が変化すること、モータが実際に追従することを確認してください。DShotは回転数制御ではありません。ビルド成功は実際の信号・ESC対応・安全な飛行を保証しません。

## ファームウェアとビルダーの分離

マイコンへ書き込むプログラムは、次の1フォルダへまとめています。

```text
firmware/pico_copter/
```

他人と共有するときは、このフォルダをそのまま取り出せます。フォルダ内には、プログラム本体、独立ビルド用`CMakeLists.txt`、ビルド手順が入っています。

```text
firmware/pico_copter/
├─ pico_copter.cpp / .hpp
├─ control.cpp / .hpp
├─ ekf.cpp / .hpp
├─ sensor.cpp / .hpp
├─ pwm.cpp / .hpp

└─ README.md
```

GitHub Actions、キャッシュ、Web配布画面などは、ファームウェアフォルダの外側に分離しています。

## github.devでファームウェアを編集する

通常のGitHubで編集したいファイルを開き、キーボードの`.`キーを押すと、同じリポジトリを`github.dev`で開けます。

主な編集対象は次のフォルダです。

```text
firmware/pico_copter/
```

編集後は、左側のソース管理から変更内容を入力して`Commit & Push`を実行します。`main`へ反映されるとGitHub Actionsが自動的にコンパイルし、成功したUF2をPagesへ公開します。Pull Requestではコンパイル確認だけを行います。

ファームウェアの変更履歴はGitで管理されるため、以前の状態はGitHubのコミット履歴から確認・復元できます。

## GitHubでUF2を生成する

1. `Settings`を開く
2. `Pages` → `Build and deployment`を開く
3. `Source`を`GitHub Actions`に設定する
4. `Actions`を開く
5. `Build Pico Copter UF2 and deploy Pages`を選ぶ
6. `Run workflow`を押す
7. 成功後、`Settings` → `Pages`に表示される公開先を開く

`main`のファームウェアやWorkflowを変更した場合も自動実行されます。Pull Requestではコンパイル確認だけを行い、Pagesへの公開は行いません。

## ファームウェアフォルダ単体でビルドする

`firmware/pico_copter`へ移動し、Pico SDKを指定してビルドします。

```bash
cd firmware/pico_copter

cmake -S . -B build \
  -DPICO_SDK_PATH=/path/to/pico-sdk \
  -DPICO_BOARD=pico \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build --parallel
```

生成物は次です。

```text
firmware/pico_copter/build/pico_copter.uf2（設定した基板向け）
```

## 依存関係

| 項目 | 固定値 |
|---|---|
| 対象ボード | `pico` / `pico2` |
| Pico SDK | `2.3.0` |
| Eigen | `3.4.0` |
| Eigenコミット | `3147391d946bb4b6c68edd901f2add6ac1f31f8c` |
| C++ | C++17 |

ファームウェアフォルダのCMakeは、`EIGEN3_INCLUDE_DIR`が指定されていない場合、公式Eigenの固定コミットを自動取得します。既にEigenを持っている場合は、次のように指定できます。

```bash
-DEIGEN3_INCLUDE_DIR=/path/to/eigen
```

GitHub ActionsではEigenを別に取得してキャッシュし、そのパスをファームウェア側のCMakeへ渡します。

## UF2の書き込み

1. Pagesで対象基板を選び、Pico 2なら`pico_copter-pico2.uf2`をダウンロードする
2. Picoの`BOOTSEL`ボタンを押したままUSB接続する
3. 表示された`RPI-RP2`ドライブへUF2をコピーする
4. コピー後、Picoが自動的に再起動する
